# 前端更新指南 —— 回收站功能

> 对应后端分支 `feature/recycle-bin`,涉及删除语义变更与 4 个新接口,前端需同步适配。

## 1. 删除语义变更(重要)

| 接口 | 变更前 | 变更后 |
|---|---|---|
| `DELETE /buckets/:id/files/:fid` | 立即物理删除(对象+记录,用量即时释放) | **进回收站**(软删):列表立即消失,对象/记录/用量保留 |
| `DELETE /buckets/:id/dirs/:fid` | 置不可用 + 后台物理清理 | **进回收站**:子树即刻不可见,数据保留 |
| `DELETE /buckets/:id/items/batch-delete` | 同上(物理删除) | 同上(全部进回收站) |

**前端影响**:
- 删除成功后的提示可改为"已移入回收站"
- 用量(桶/用户配额)不会因删除立即释放——用户删除大量文件后配额仍被占用,属预期行为(回收站占用量,真正清除/超保留期后才归还)
- 回收站文件默认保留 30 天(`recycle_bin.retention_days`,可配),到期由后台自动物理清除

## 2. 新接口(均需登录)

### 2.1 回收站列表(文件/文件夹分两个接口)

```
GET /recycle-bin/files?page=&page_size=&cursor=&key=&order=&user_id=
GET /recycle-bin/folders?page=&page_size=&cursor=&key=&order=&user_id=
```

- 返回**统一分页结构**(与后端 common 分页封装一致):

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": 12,
        "name": "a.txt",
        "file_size": 1024,
        "uploaded_by": 3,
        "deleted_at": "2026-08-28T06:00:00Z",
        "...": "其余字段同文件元数据"
      }
    ],
    "total": 42,
    "page": 1,
    "page_size": 50,
    "total_pages": 1,
    "has_more": false,
    "next_cursor": 12
  }
}
```

- `list` 内条目带 **`deleted_at`**(进入回收站时间,可展示);文件夹条目还有 `isable=false`
- `user_id` 缺省 = 当前用户;传入他人 ID 时仅管理员可查(非管理员 403)
- `key` 为文件名前缀模糊搜索(可选);`cursor` 深翻页游标(配合 `order` 使用)

### 2.2 永久删除回收站文件(提前清除)

```
DELETE /recycle-bin/files/:id
```

- 成功 204;非回收站条目 404;非归属者且非管理员 403
- 删除后不可恢复(对象+记录+用量立即释放)

### 2.3 恢复回收站文件

```
POST /recycle-bin/files/:id/restore
```

- 成功返回恢复后的文件记录(200)
- **注意恢复时的两个自动行为**:
  1. 原所在文件夹已被删除 → 恢复到**桶根**
  2. 目标位置已有同名文件 → **自动重命名**为 `name (1).ext` 等(与上传同名处理一致)
- 前端可在恢复后按返回值刷新对应目录,或提示"已恢复(重命名/移至根目录)"

## 3. 交互建议

- 回收站页:列表(文件/文件夹两个 Tab 或合并)、恢复按钮、永久删除按钮(需二次确认)
- 删除确认弹窗文案:"删除后将进入回收站,30 天后自动清除"
- 永久删除/恢复失败时按 404/403 给出对应提示

## 4. 其他说明

- 回收站**文件夹**的恢复/永久删除接口暂未提供(本期仅文件)
- 批量恢复/清空回收站为后续迭代
