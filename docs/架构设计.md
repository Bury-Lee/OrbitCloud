# OrbitCloud 架构设计

> 分布式网盘:元数据由 GORM 管理(SQLite 开发 / PostgreSQL 生产,支持读写分离),
> 文件数据经 S3 协议写入对象存储(兼容 RustFS / MinIO / OSS / COS / OBS),
> 前端 Vue3 + Element Plus。

## 1. 总体分层

```
┌─────────────────────────────────────────────────────────────┐
│ main(入口)                                                  │
│   启动:配置 → 日志 → DB → JWT → 存储 → 协程池               │
│   运行:HTTP 服务 + 后台任务 + 优雅停机(10s 超时)             │
├─────────────────────────────────────────────────────────────┤
│ api(HTTP 接入层)                                            │
│   路由注册 / 鉴权中间件 / 参数校验 / 哨兵错误→HTTP 状态码    │
│   纯无状态:AppGroup 聚合 Auth/User/Bucket/File/Share/...    │
├─────────────────────────────────────────────────────────────┤
│ server(业务层:包级函数,函数内直接访问 core 单例)            │
├─────────────────────────────────────────────────────────────┤
│ cron(定时任务) │ flag(命令行指令)                           │
├─────────────────────────────────────────────────────────────┤
│ model(GORM 模型)  common(哨兵错误/统一响应/分页/校验)       │
│ utils(桶名编码/采样 MD5/ByteRange)                          │
├─────────────────────────────────────────────────────────────┤
│ core(最底层:全局单例,不 import 上层)                        │
│   GlobalConfig / DB / JWT / Pool / Storage(ObjectStorage)   │
└─────────────────────────────────────────────────────────────┘
```

**依赖规则**:上层只能向下引用;`core` 是最底层,不 import 任何业务包,避免循环引用。

## 2. 数据模型

| 表 | 说明 | 删除策略 |
|---|---|---|
| `users` | 账号;`PermissionLevel` 分级(0=超级管理员 / 1=管理员 / 3=普通用户,可在 0~9 区间扩展);bcrypt 密码 | 软删 |
| `buckets` | 存储桶;`Quota`/`UsedSpace` 容量配额 | 硬删(先置禁用,后台级联) |
| `folders` | 目录树节点,`ParentID` 自引用(0=桶根虚拟) | 硬删(先置 `Isable=false`,后台深度优先) |
| `files` | 文件条目,`FolderID=0` = 桶根;对象 key = 主键 ID | 硬删 |
| `user_groups` / `user_group_members` | 用户组 + 成员(条目级可见性 ACL) | 软删 |
| `refresh_tokens` | 登录刷新令牌 | 软删 + cron 定时硬删 |
| `share_links` | 分享,`ItemType` 区分 file/folder | 软删 + cron 清理过期 |
| `operation_logs` | 操作审计(可选开启) | cron 按 `retention_days` 分批清理 |
| `delete_tasks` / `copy_tasks` | 后台删除/复制任务 | 完成后硬删 |

统一约定:所有表内嵌 `gorm.Model`(ID/CreatedAt/UpdatedAt/DeletedAt);
状态字段 `int`:1 正常 / 0 禁用;时间统一 UTC 存储;唯一索引兜底并发创建。

## 3. 权限模型

- 分级 `PermissionLevel`,数值越小权限越高;已定义 0 = 超级管理员、1 = 管理员、2 = 特殊用户(预留档位,行为同普通用户)、3 = 普通用户,可在 0~9 区间按实际需求扩展;
- 管理员判定统一为 `PermissionLevel.IsAdmin()`(即 0 / 1);
- 权限 0 **只能**经命令行 `--add-superadmin` 创建(HTTP API 一律归一为普通用户);
- 管理员改他人权限/状态/删除时,操作者权限须**严格高于**目标;
- 桶级:访问等级 `permission_level` 与管理等级 `manage_permission_level` 独立(管理等级 0 = 跟随访问等级,管理要求不得松于访问);配置 `bucket.admin_create_only` 可限制仅管理员建桶;
- 条目级 ACL:`VisibleToGroups`(JSON 组 ID 列表,空 = 不限制),叠加用户组可见性;非空时仅管理员/组内成员可见(上传者不自动放行,deny-by-default)。

## 4. 存储设计

### 4.1 对象键设计

- 文件实体在对象存储中的 **key = 文件记录主键 ID**;
- **桶名 = `utils.BucketEncoder(桶ID)`(36 进制编码)**;
- 不依赖文件名/路径 → 重命名/移动只改元数据,零对象搬迁。

### 4.2 双驱动

| driver | 行为 | 适用 |
|---|---|---|
| `s3` | 分片以 S3 对象写入对象存储(多节点多副本) | 生产推荐 |
| `local` | 分片写本地目录(节点 `path`) | 开发/单机 |

### 4.3 分片与副本

- 文件按 `chunk_size`(MB)切分,分片分发到不同节点;
- `min_replicas` 每分片副本数;副本修复由定时扫描触发(`repair_interval`),
  带并发上限防"修复风暴";
- 节点健康检查:连续 `fail_threshold` 次失败 → inactive 剔除,不再分配新写入。

## 5. 关键流程

### 5.1 上传

```
HTTP multipart(流式,不整读内存)
  → server.UploadFile:写入对象存储(Put 对象)
  → 写 files 记录 / 更新 bucket.used_space
补偿:对象写失败 → 删记录;元数据更新失败 → 清对象(不留空洞/孤儿)
```

### 5.2 下载 / 预览

- 流式返回(`write_timeout=0`),支持 `Range` 断点续传(416 带 `Content-Range`);
- `GET /stream` 用 QueryToken 鉴权,供播放器/内嵌页临时访问;
- 批量下载走 zip(fflate 前端打包或后端 zip,失败项逐条返回)。

### 5.3 删除 / 复制(后台任务,崩溃可续跑)

```
目标置不可用(isable=false / 桶 status=0)
  → 落 delete_tasks / copy_tasks
  → 后台深度优先处理:"边删边查",子项仍分页遍历
  → 任务级乐观锁防重复处理
  → 进程崩溃重启后 Resume 续跑未完成任务
```

### 5.4 批量操作

≤100 条,逐条独立处理,失败不影响其它;`batch-delete / batch-copy / batch-move /
batch-download` 四个端点。

## 6. 并发与健壮性

| 机制 | 说明 |
|---|---|
| 全局协程池 | `agilePool`,`max_workers`/`queue_size` 统一限制并发;HTTP handler 内并行任务统一经其提交 |
| 优雅停机 | 监听 SIGINT/SIGTERM → HTTP Shutdown(10s 超时)→ 关协程池 → 关 DB |
| panic 处理 | main 顶部 defer 打印堆栈后崩溃(不恢复,保证现场可查);500 对外统一 "internal error" |
| 启动自检 | 配置缺失/非法、存储不可用、DB 连不上 → 启动即终止,避免运行期 panic |
| 定时任务 | cron 每小时清理过期日志/刷新令牌/分享;副本修复扫描;启动时 Resume 任务 |

## 7. 配置与启动顺序

```
main.go
  1. flag.RunPreInit      (-initConfig,无需任何初始化)
  2. appinit.InitConfig   → core.GlobalConfig    (工作目录 ./config.yaml,embed 默认)
  3. appinit.InitLog      (轮转/可选入库)
  4. appinit.InitDB       → core.DB              (AutoMigrate + 重连)
  5. AttachLogDBWriter    (db_level 非空时)
  6. appinit.InitJWT      → core.JWT
  7. appinit.InitStorage  → core.Storage         (失败即终止)
  8. appinit.InitPool     → core.Pool
  9. flag.Run             (--add-superadmin / --version / --help)
 10. api.Router() + http.Server 启动(协程)
 11. cron.Resume* + cron.Start
 12. 等待退出信号 → 优雅停机
```

## 8. 前端

- Vue 3.5 + Vite + TS + Element Plus + Pinia + Vue Router + Axios;
- 开发代理:`/api` → `127.0.0.1:8080`(同源,无需 CORS);
- Axios 统一解包;401 → 刷新令牌轮换后重放原请求(并发共享刷新 Promise);
- 下载/预览走独立 blob 实例,避免拦截器误拆二进制流;
- 生产:`dist/` 由 Nginx 托管,SPA history 回退 + `/api` 反代(见部署指南 §5)。
