# SMB 网关代码走查指南(对接实现全览)

> 本文是 SMB 网关(Go 服务端 + Rust 网关)对接实现的**逐文件走查清单**,
> 供代码审查使用。每个文件给出职责、关键函数、设计决策与注意事项,
> 审查时可对照签名与实现逐项核对。
>
> 配套文档:
> - `docs/smb-gateway/` 01~07 设计文档(帧协议/连接生命周期/桶注册表等)
> - `docs/smb-gateway/08-接入落地记录.md`(改动概览/部署流程/S3 随机写方案)
> - 灰度测试(52 项,内部测试不随仓库发布)

## 1. 组件架构

```text
Windows Explorer / Linux cifs(SMB 2.02~3.1.1,2445/445)
        │
        ▼
Rust 网关(smb_server/rust,ixr-smb-server 0.5.1 + patched-ixr 补丁)
   ├─ SmbServer:协议接入(协商/会话/TREE/CREATE/IO/QUERY/SET/CHANGE_NOTIFY)
   ├─ RemoteBackend/RemoteHandle:操作转发(私有 TCP 帧协议)
   │        │  127.0.0.1:9101(共享密钥 + 双向 HMAC 握手)
   │        ▼
Go 侧网关组件(smb_server/go,嵌入主程序)
   ├─ gateway.go:Socket 帧服务(握手/心跳/请求池/句柄表/变更广播)
   ├─ auth.go:动态认证(用户/NT hash/可见共享/快照/变更检测)
   ├─ file_ops.go:文件操作(open/read/write/…/递归删除/写回缓存)
   ├─ wire.go:装配(读密钥/构造池/注入推送)
   ├─ types.go:协议契约(帧头/操作码/参数/结果/错误码)
   └─ main.go:双服务接线(HTTP 8080 + 私有 Socket 9101)
```

## 3. Go 侧实现走查

### 3.1 main.go —— 双服务接线

```go
// 初始化(HTTP 与 SMB 网关共用 core 单例)
appinit.InitConfig → InitLog → InitDB → InitJWT → InitStorage → 池
// 第 3.5 步:SMB 网关组件(与 HTTP 并行)
smbGW, err := smbgateway.BuildGateway(cfg.SmbGateway)   // wire.go
go smbGW.Serve(smbCtx)                                   // 私有 Socket 9101
go smbGW.Auth().WatchAndPush(smbCtx)                     // 变更推送常驻
// 第 5 步:优雅停机
smbCancel(); smbGW.Shutdown(shutdownCtx)
```

审查要点:
- SMB 网关在 `flag.Run` 之后启动(保证 DB 就绪);
- 网关启动失败 → `log.Fatalf` 终止(与 HTTP 一致:基础设施不可用即终止);
- WatchAndPush 与 Serve 共用 smbCtx,停机一并取消。

### 3.2 types.go —— 协议契约

- 帧头 16 字节大端:`magic("OCST") + version(1) + flags + msgType + seq + bodyLen`;
- 消息类型:`MSG_HELLO/HELLO_ACK/HEARTBEAT/AUTH_PUSH(0x15)/OPERATE(0x201)/OPERATE_RESP(0x202)/ERR_RESP(0x8001)`;
- 操作码:1~14(查询用户/ACL/快照/open/read/write/flush/stat/set_times/truncate/list_dir/close/unlink/rename);
- **总操作 JSON 单次反序列化**(OperateRequest.Route 校验 Code 唯一性);
- 错误映射 `wrapErrResp`:`ErrNotFound→1, ErrForbidden→2, ErrConflict→3, errNotEmpty→4, errIsDirectory→5, errNotADirectory→6, ErrInvalidInput→12, 其余→7`;
- `OpenArgs/UnlinkArgs/RenameArgs` 含 `bucketId`(共享上下文直传,不依赖路径首段)。

### 3.3 gateway.go —— 帧服务

- `Serve`:Accept 循环 → 每连接 `handleConn`(协程)→ 停机广播 + WaitGroup;
- `handshake`:双向 HMAC(HELLO:clientId:nonce → serverNonce → VERIFY:serverNonce),10s 超时;
- `handleRequest`:请求池 `Acquire`(reject 模式满则回 ERR 背压帧)→ dispatch → 回写;
- `dispatch`:MSG_OPERATE 拆 `[4B jsonLen]+JSON+流段` → 单次反序列化 → `Route(ctx,...)` → 组装;
- 连接 ID(connIDKey)注入 ctx:句柄归属 → 断连 `CloseAllByConn` 回收;
- `pushToAll`:遍历活跃连接发 MSG_AUTH_PUSH(单向)。

### 3.4 auth.go —— 认证与变更

- `QueryUser`:users 表按 username,Status=1 才返回(含 nt_hash);
- `QuerySharesForUser` / `Snapshot`:桶可见性 = `status=1 AND (owner_id=? OR permission_level >= user)`(与 API 层同口径);
- `WatchAndPush`:**每 60s** 快照 diff(与 Rust 侧全量对账周期对齐;服务端认证/文件操作实时校验用户与桶状态,客户端内存表允许滞后):
  - 用户/共享增量(upsert/delete);
  - **目录变更指纹**:files/folders 两表(count + MAX(updated_at))变化 → 推 `AclEntry{op:"notify", kind:"dir"}`(驱动 CHANGE_NOTIFY);
- `SetUserNTHash`/`SyncUserNTHashFromPassword`:写 nt_hash + 推送 upsert;
- `dirFingerprint` 结构体零值作为初值——首轮必然"变化"推一次(可接受)。

审查点:指纹是**全局**(不区分桶/目录),任一表变更触发全部挂起通知重枚举——已知局限。

### 3.5 file_ops.go —— 文件操作(核心)

| 函数 | 语义要点 |
|---|---|
| `Open` | 共享上下文三级解析(缓存→路径首段→bucketId);**根路径(空)返回虚拟根目录句柄(folderID=0)**;目录分支 `intent=open` 不存在→NotFound(不隐式建目录,存在性按父链解析);文件分支目录存在+non_directory→IsDirectory,否则按目录打开;intent 五态(open/create/open_or_create/overwrite_or_create/truncate) |
| `Read` | 写回缓存段视图 + GetRange 间隙合并;**对象缺失/越界 → 短读(EOF),绝不零填充**;416 在 GetRange 与 io.ReadAll 两阶段均判定 |
| `Write` | ApplyWrite 段合并;超 4MiB 提前 Flush;更新 h.size |
| `Flush` | FlushToStorage + **桶用量对称更新**(delta 累加/扣减)+ FileSize 落库 |
| `Close` | Flush + FileSize/用量更新 + deleteOnClose → Unlink |
| `Stat` | **folderID=0(桶根)返回桶级元信息**(虚拟根);文件叠加写回缓存增量 |
| `ListDir` | folderID=0 查桶根(folders parent=0 + files folder=0) |
| `Unlink` | 目录 → **递归删除**;文件 → server.DeleteFile |
| `Rename` | resolveDir 父链(带 bucket)→ 文件/目录分支 MoveFile/MoveFolder |
| `deleteFolderRecursive` | 深度优先:子文件夹→文件(删对象+记录+用量扣减)→硬删本目录 |
| `WriteBackCache` | 段表合并(后写覆盖)/Ranges 快照/FlushToStorage(间隙 GetRange+零填充拼装,truncateTo 裁剪) |

**写回缓存(解决 S3 无随机写)**:见 `08-接入落地记录.md` §5。

**已知边界**:
- `SetTimes` 为 no-op;
- `resolveDir` 父链缺段且写 intent 时自动 mkdir -p;
- 递归删除失败即中止(可重试续跑)。

### 3.6 wire.go —— 装配

```go
BuildGateway(cfg):
  key = loadSharedKey(cfg.SharedKeyEnv)        // env ≥16 字节,留空跳过
  pool = core.NewAdmissionPool(MaxConcurrent, ChannelBuffer, Reject)
  auth = NewAuthService(core.DB)
  files = NewFileOpsService(core.Storage, NewHandleRegistry())
  gw = NewGateway(ListenAddr, key, pool, auth, files)
  auth.SetPushFunc(gw.pushToAll)               // 推送直连网关广播
```

### 3.7 NT hash 全链路

- 写入点:`server/user.go`(Register/UpdateMe/UpdateUser)+ `flag/enter.go`(--add-superadmin),经 `utils.NtHashOf` = MD4(UTF-16LE(明文));
- 落库:`users.nt_hash`(varchar(32),AutoMigrate 自动建列);
- 下发:仅经 SMB 网关 `QueryUser` 返回;**HTTP 响应全部脱敏**(GetUser/ListUsers/Register/UpdateUser 均清空 NtHash);
- Rust 侧:patched-ixr `ConfigHandle::add_user_nt_hash`(hex→[u8;16]→UserCreds)。

## 4. Rust 侧实现走查

### 4.1 main.rs —— 启动与重连

```text
parse_args → load_config → load_shared_key → connect_with_retry(1s→5s→30s)
→ SmbServer::builder().listen(netbios_name).build()
→ sync_loop(conn, registry, handle, server_state, push_rx, interval)
→ 连接监督任务(每 2s 探测 is_alive;断线重连 + abort 旧 sync + 重启)
→ bind + serve(ctrl-c 优雅关闭)
```

审查点:
- 重连后 `sync_loop` 重新拉全量快照 → registry 重建(RemoteBackend 用新 conn);
- `server_state` 为 `Arc<ServerState>`(patched-ixr re-export),供 CHANGE_NOTIFY 完成;
- 曾出现问题:重连后快照 JSON 解析失败(used_space 负数)→ 共享注册不更新 → 旧死连接报错;已由用量对称修复。

### 4.2 remote_backend.rs

- `GatewayClient`:send_queue(管道)/seq_counter/pending(seq→oneshot)/push_tx/shared_key/**alive 标志**;
- `connect` 返回 `(Arc<Self>, push_rx)`;reader/writer/heartbeat 任一退出 → `mark_dead`;
- `call`:seq→oneshot,30s 超时;断线给全部 pending 投 `ERR_GATEWAY_DOWN`;
- `RemoteBackend::open/unlink/rename`:Args 携带 `bucket_id`(共享上下文);
- `RemoteHandle::read`:校验 `ReadResult.Length == 流段长度`;
- `map_gateway_err`:完整映射(ERR_IO/GATEWAY_DOWN/TIMEOUT→Io 等)。

### 4.3 registry.rs

- 桶实例表:`HashMap<share_name, BucketInstance>`(RwLock);
- `upsert`:pre-remove(UnknownShare 忽略)→ add_share → 逐用户 grant;幂等;
- `delete`:remove_share(UnknownShare 忽略)→ 移除实例;
- `apply_snapshot`:快照外实例下线,其余 upsert;
- `build_share`:**AuthenticatedOnly**(不用 public,避免 Public+users 冲突)。

### 4.4 sync.rs

- `sync_loop`:启动全量对账 → 常驻消费 push_rx + 定时 reconcile;
- **notify 处理**:`op=="notify" && kind=="dir"` → `server_state.complete_change_notifies()`(向全部挂起监视发 STATUS_NOTIFY_ENUM_DIR → 客户端重枚举);
- `apply_snapshot`:clear_users → add_user_nt_hash(跳过禁用/无 hash)→ registry.apply_snapshot;
- `apply_push`:六分支(user/share/acl × upsert/delete)。

## 6. 关键流程时序

### 6.1 目录变更自动刷新(变更驱动)

```text
用户 SMB 写入(WRITE→CLOSE→Flush→对象+用量+FileSize)
   │(≤10s)
Go WatchAndPush:指纹变化 → push AclEntry{op:notify, kind:dir}
   │(9101 单向帧)
Rust sync_loop → complete_change_notifies
   │(对挂起的 CHANGE_NOTIFY 回 STATUS_NOTIFY_ENUM_DIR)
Windows 资源管理器 → 重新枚举目录 → 界面自动刷新
```

### 6.2 断线自愈

```text
orbitcloud 重启 → smb-gateway 检测连接断开(alive=false)
→ 监督任务重连(退避)→ 新 GatewayClient + push_rx
→ 重启 sync_loop → 全量快照 → registry 重建(新 conn)
→ 共享/用户恢复,客户端无需重挂载
```

### 6.3 SMB 写入落盘(S3 无随机写)

```text
SMB WRITE(offset,data) → WriteBackCache.ApplyWrite(段表合并)
→ CLOSE/FLUSH → FlushToStorage:
   间隙 GetRange(对象缺失→零填充) + 缓存段 + truncate 裁剪
→ Put 整体对象 → FileSize/桶用量更新
```

## 8. 已知限制与后续 TODO

1. `statfs`(容量栏):已能返回(测试通过),但配额/已用上报为伪值(1PiB/4KiB);
2. `SetTimes` no-op(时间戳由后端记录维护);
3. 目录变更通知为**全局指纹**(不区分桶/目录),枚举开销随规模增长;
4. Web 端下载"对象缺失"的文件:0 字节已兜底,非 0 字节仍 404(`server/file_download.go` 修复未提交);
5. 大文件读取较慢(50MB≈36s,RustFS 范围读),建议并行分块;
6. 递归删除大目录同步执行,超深目录可能超时;
7. `used_space` 依赖对称维护(写入累加/删除扣减),极端异常可能漂移,建议定时重算。
