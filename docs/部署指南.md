# OrbitCloud 部署指南

> 适用版本:任意 ≥ 0.1.0;建议阅读顺序:[快速开始](#1-快速开始)→ [生产部署](#2-生产部署)→ [对象存储](#3-对象存储对接)→ [数据库](#4-数据库)→ [反向代理](#5-反向代理)→ [运维](#6-运维)。

---

## 1. 快速开始(体验 / 开发)

环境要求:Go ≥ 1.25(后端)、Node.js ≥ 18(前端,可选)。

### 1.1 获取二进制

方式 A —— 直接编译(任意平台):

```bash
go build -trimpath -o orbitcloud .
```

方式 B —— 用仓库脚本一键编译三个系统(Windows 上执行,产物在 `build/dist/`):

```bat
build\build.bat                          :: 默认:windows/linux/darwin × amd64/arm64
build\build.bat -Frontend -Package       :: 连带前端构建并打 zip/tar.gz 包
```

详见 [构建脚本说明](构建与发布.md)(若存在)或 `build/build.ps1` 头部注释。

### 1.2 初始化并启动

```bash
./orbitcloud -initConfig                             # 首次:生成 ./config.yaml(内置默认配置,含全部可配置项)
./orbitcloud --add-superadmin admin admin123456      # 创建超级管理员(权限 0,仅此通道可创建;密码 ≥ 8 位)
./orbitcloud                                         # 启动,默认监听 0.0.0.0:8080
```

- 未启动对象存储时,把 `config.yaml` 中 `storage.driver` 改为 `local` 即可本地跑通全流程(对象直接写本地目录,不依赖 S3);
- 前端开发模式:`cd frontend && npm install && npm run dev`,Vite 已代理 `/api` → `127.0.0.1:8080`,无需配置 CORS。

## 2. 生产部署

### 2.1 整体架构

```
客户端(浏览器)
   │  https
   ▼
Nginx(443)
   ├── /        → 前端静态资源(dist/)
   └── /api/    → 反向代理 → orbitcloud(:8080)
                              ├── PostgreSQL(元数据,可读写分离)
                              └── 对象存储(S3 协议:RustFS / MinIO / OSS ...)
```

### 2.2 部署步骤(以 Linux + systemd 为例)

1. **编译**:在任意机器执行 `build/build.bat -Frontend`(或 `build/build.sh`),取
   `build/dist/orbitcloud-linux-amd64-<version>/` 目录(含二进制与 `web/` 前端产物)。

2. **落位**:

```bash
sudo mkdir -p /opt/orbitcloud/{bin,config,logs,data}
sudo cp orbitcloud /opt/orbitcloud/bin/
sudo cp -r web /opt/orbitcloud/web          # 前端产物(由 Nginx 托管)
```

3. **初始化配置**:

```bash
cd /opt/orbitcloud/config
/opt/orbitcloud/bin/orbitcloud -initConfig
# 编辑 config.yaml:生产必改 4 项 ↓
#   jwt.secret            → 长随机串(或用环境变量 ORBITCLOUD_JWT_SECRET)
#   storage.access_key/secret_key → 对象存储真实凭据
#   database.sources[0].dsn → postgres 连接串(或用 ORBITCLOUD_DB_DSN)
#   nodes[].endpoint      → 真实 S3 端点
```

4. **创建超级管理员并试启动**:

```bash
/opt/orbitcloud/bin/orbitcloud --add-superadmin admin '<强密码>'
/opt/orbitcloud/bin/orbitcloud &            # 前台先跑一次确认日志无 ERROR
```

5. **注册 systemd 服务** `/etc/systemd/system/orbitcloud.service`:

```ini
[Unit]
Description=OrbitCloud distributed netdisk
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/orbitcloud/config
Environment="ORBITCLOUD_JWT_SECRET=<长随机串>"
Environment="ORBITCLOUD_DB_DSN=postgres://orbitcloud:pass@127.0.0.1:5432/orbitcloud?sslmode=disable"
ExecStart=/opt/orbitcloud/bin/orbitcloud
Restart=always
RestartSec=3
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now orbitcloud
sudo systemctl status orbitcloud          # 验证 Active: active (running)
```

6. **部署前端 + Nginx**:见 [5. 反向代理](#5-反向代理)。

### 2.3 Windows 生产(服务化)

用 [NSSM](https://nssm.cc/) 将二进制注册为 Windows 服务:

```bat
nssm install OrbitCloud "C:\orbitcloud\orbitcloud.exe"
nssm set OrbitCloud AppDirectory "C:\orbitcloud\config"
nssm set OrbitCloud AppEnvironmentExtra "ORBITCLOUD_JWT_SECRET=..." "ORBITCLOUD_DB_DSN=..."
nssm set OrbitCloud AppStdout "C:\orbitcloud\logs\stdout.log"
nssm set OrbitCloud AppStderr "C:\orbitcloud\logs\stderr.log"
nssm start OrbitCloud
```

### 2.4 Docker Compose(仓库内置 `docker-compose.yml`)

> 仓库自带的 compose 是**开发用**的:挂载源码、golang:1.25 镜像内编译运行。
> 生产建议按下面方式自建镜像。

生产镜像 `Dockerfile`(示例):

```dockerfile
FROM golang:1.25 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o /out/orbitcloud .

FROM alpine:3.20
RUN apk add --no-cache ca-certificates tzdata
COPY --from=build /out/orbitcloud /usr/local/bin/orbitcloud
WORKDIR /data
EXPOSE 8080
ENTRYPOINT ["orbitcloud"]
```

`docker-compose.yml`(生产,含 PostgreSQL 与 MinIO 示例):

```yaml
services:
  orbitcloud:
    build: .
    container_name: orbitcloud
    ports: ["8080:8080"]
    environment:
      ORBITCLOUD_JWT_SECRET: "请替换为长随机串"
      ORBITCLOUD_DB_DSN: "postgres://orbitcloud:pass@postgres:5432/orbitcloud?sslmode=disable"
      ORBITCLOUD_S3_ACCESS_KEY: "minioadmin"
      ORBITCLOUD_S3_SECRET_KEY: "minioadmin"
    volumes:
      - ./config.yaml:/data/config.yaml   # 先 -initConfig 生成
      - ./data:/data/.orbitcloud
      - ./logs:/data/logs
    depends_on: [postgres, minio]
    restart: unless-stopped

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: orbitcloud
      POSTGRES_PASSWORD: pass
      POSTGRES_DB: orbitcloud
    volumes: [pgdata:/var/lib/postgresql/data]
    restart: unless-stopped

  minio:
    image: minio/minio:latest
    command: server /data --console-address ":9001"
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    volumes: [miniodata:/data]
    restart: unless-stopped

volumes:
  pgdata:
  miniodata:
```

启动流程:先 `docker compose up -d postgres minio`,再在容器里执行
`docker compose exec orbitcloud orbitcloud -initConfig`(或挂载已生成的 config.yaml),
然后 `orbitcloud --add-superadmin admin '<强密码>'`。

## 3. 对象存储对接

- **兼容**:任何 S3 协议实现(RustFS / MinIO / AWS S3 / 阿里云 OSS / 腾讯云 COS / 华为云 OBS)。
  `config.yaml → storage.provider` 取 `minio | rustfs | s3 | oss | cos | obs` 之一;
- **驱动选择**:

| driver | 说明 | 适用 |
|---|---|---|
| `s3` | 对象写入对象存储,key = 文件记录主键 ID,桶名 = `utils.BucketEncoder(桶ID)`(36 进制) | 生产推荐 |
| `local` | 对象直接写本地目录(节点 `path` 指定) | 开发 / 单机测试,无需对象存储 |

- **多节点**:`storage.nodes` 列表注册多个存储节点,全局凭据在 `storage` 段,节点可逐项覆盖;
  支持容量配额(`max_space`,GB)与健康检查自动剔除(`health.fail_threshold` 次失败标记 inactive);
- 生产必改:`access_key` / `secret_key`(建议环境变量注入)、`nodes[].endpoint`。

## 4. 数据库

| 场景 | 推荐 | 说明 |
|---|---|---|
| 开发 / 单机 | SQLite(`orbitcloud.db`,自动创建) | 零依赖;不支持读写分离,配了 `replicas` 会报错 |
| 生产 | PostgreSQL | 可读写分离:`sources` 写库(首个为主库,负责建表)+ `replicas` 读库负载均衡 |

- 建表:启动时 GORM AutoMigrate 自动完成,无需手写迁移 SQL;
- DSN 示例:`postgres://user:pass@127.0.0.1:5432/orbitcloud?sslmode=disable`;
- 多写库需库间主主复制;首个写库承担建表与审计;
- 敏感连接串建议环境变量 `ORBITCLOUD_DB_DSN` 注入,不落盘。

## 5. 反向代理

前端(SPA,history 路由)与 API 反代的 Nginx 配置:

```nginx
server {
    listen 80;
    server_name disk.example.com;

    root /opt/orbitcloud/web;                    # 前端构建产物(构建脚本已附带至包内 web/)
    index index.html;

    # SPA history 路由回退
    location / { try_files $uri $uri/ /index.html; }

    # API 反代(注意保留路径:前端请求为相对路径 /api/v1/...)
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 下载/批量下载为流式与长连接,关闭代理缓冲
        proxy_buffering off;
        proxy_read_timeout 600s;
        client_max_body_size 0;                  # 大文件上传不限制(或按需设置,如 20g)
    }
}
```

HTTPS 建议用 certbot 自动签发,或按站点补 `listen 443 ssl;`。

## 6. 运维

### 6.1 备份与迁移

| 对象 | 备份内容 | 说明 |
|---|---|---|
| 元数据 | PostgreSQL dump(`pg_dump`) | 建表自愈,只需恢复数据 |
| 对象数据 | 对象存储桶快照 / 复制 | 与元数据**同时间点**备份才一致 |
| 配置 | `config.yaml` | 含凭据,注意保密 |

迁移:同版本迁移只需在新机器恢复数据库 + 指向同一对象存储 + 同配置即可。

### 6.2 日志

- 默认 stdout;配置 `log.output_path` 后按日期落盘轮转:`{目录}/{YYYY-MM-DD}/{前缀}-{HH-MM-SS}.log`;
- `log.max_size` 控制单文件大小切换(KB);`log.db_level` 开启日志入库(谨慎,量大会膨胀);
- 过期日志/令牌/分享由定时任务每小时清理(参照 `log.retention_days`)。

### 6.3 常见问题排查

| 现象 | 排查 |
|---|---|
| 启动报 `load config` | `config.yaml` 缺失/非法;先 `-initConfig` 再改 |
| 启动报存储不可用 | 对象存储未启动/端点错/凭据错;`driver: local` 可绕过 |
| 启动持续重试连库 | `database.sources` DSN 错误;DB 未就绪 |
| 502(登录/上传大文件) | `client_max_body_size` 太小或后端超时;见上面 Nginx 配置 |
| 上传成功但列表没有 | 桶/目录 ACL 或可见组设置;检查 `visibility` 接口返回 |
| 中文乱码日志 | Windows 控制台:先 `chcp 65001`,或直接看落盘日志文件 |

### 6.4 平滑升级

1. 备份 DB(与对象存储快照);
2. 停旧进程 → 替换二进制(版本升级会触发 AutoMigrate 增量建表);
3. `orbitcloud --version` 确认版本 → 启动新进程;
4. 观察日志无 ERROR,抽查上传/下载/分享各一条链路。
