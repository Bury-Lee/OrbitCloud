# 用户组与文件夹可见组 — 演示配置操作文档

> 适用版本:OrbitCloud 后端 API 8080 / SMB 网关 445
> 模拟场景:**院内科室文件共享与科室间数据隔离**

---

## 1. 场景说明(模拟什么)

模拟**医院院内多科室文件共享**场景:不同科室(信息科、临床一科)共享同一台私有化网盘服务器,但科室目录**互相隔离**——每个科室只能看到本科室的文件夹,其他科室的目录不可见、不可进入。

核心机制 = **文件夹可见组(条目级 ACL)**:

```
账号级(权限 0-9) → 桶级(访问等级) → 条目级(文件夹可见组)
                                    ↑ 本次演示的重点
```

- 文件夹设置"可见组"后,只有**组内成员**能在列表里看到它、进入它;
- 无权限用户列表直接不显示该文件夹,强行访问返回 403;
- 父子目录路径回溯逐级校验(上级不可见则下级不可达)。

演示对照:

| 账号 | 所属组 | 能看到 | 看不到 |
|---|---|---|---|
| admin | 超管(无组) | 全部 | — |
| demo_zhang | 信息科 | SMB演示素材、新建文件夹 | dsadsadasd |
| demo_li | 临床一科 | SMB演示素材、dsadsadasd | 新建文件夹 |
| demo_wang | 无组(对照) | 仅 SMB演示素材 | 两个科室目录都看不到 |

## 3. 配置步骤

### 3.1 管理员登录获取 Token

```bash
curl -X POST http://10.15.109.17:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123456"}'
```

返回:

```json
{"code":0,"data":{"access_token":"<TOKEN>","user":{...}}}
```

后续请求统一带 `Authorization: Bearer <TOKEN>`。

### 3.2 创建演示用户(管理员)

```bash
curl -X POST http://10.15.109.17:8080/api/v1/auth/register \
  -H 'Content-Type: application/json' -H "Authorization: Bearer <TOKEN>" \
  -d '{"username":"demo_zhang","password":"Demo123456","permission_level":3}'

# 同样创建 demo_li、demo_wang
```

| 接口 | 说明 |
|---|---|
| `POST /api/v1/auth/register` | 管理员创建用户;`permission_level` 3=普通用户(0/1 为管理员,仅命令行可建 0) |

### 3.3 创建用户组(管理员)

```bash
curl -X POST http://10.15.109.17:8080/api/v1/groups \
  -H 'Content-Type: application/json' -H "Authorization: Bearer <TOKEN>" \
  -d '{"name":"信息科","description":"信息科科室共享组"}'

curl -X POST http://10.15.109.17:8080/api/v1/groups \
  -H 'Content-Type: application/json' -H "Authorization: Bearer <TOKEN>" \
  -d '{"name":"临床一科","description":"临床一科科室共享组"}'
```

返回中记录组 ID(本次:信息科=1,临床一科=2)。

### 3.4 添加组成员(管理员)

```bash
# demo_zhang 加入 信息科(组1)
curl -X POST http://10.15.109.17:8080/api/v1/groups/1/members \
  -H 'Content-Type: application/json' -H "Authorization: Bearer <TOKEN>" \
  -d '{"user_id":<demo_zhang的ID>}'

# demo_li 加入 临床一科(组2)
curl -X POST http://10.15.109.17:8080/api/v1/groups/2/members \
  -H 'Content-Type: application/json' -H "Authorization: Bearer <TOKEN>" \
  -d '{"user_id":<demo_li的ID>}'
```

### 3.5 查看桶内文件夹 ID

```bash
curl -X GET "http://10.15.109.17:8080/api/v1/buckets/1/files?path=/&page_size=100" \
  -H "Authorization: Bearer <TOKEN>"
```

返回 `data.folders[]`:

```json
"folders":[
  {"ID":5,"Name":"SMB演示素材",...},
  {"ID":4,"Name":"dsadsadasd",...},
  {"ID":1,"Name":"新建文件夹",...}
]
```

### 3.6 设置文件夹可见组(创建者或管理员)

```bash
# 新建文件夹(目录ID=1) → 仅信息科(组1)可见
curl -X PUT http://10.15.109.17:8080/api/v1/buckets/1/dirs/1/visibility \
  -H 'Content-Type: application/json' -H "Authorization: Bearer <TOKEN>" \
  -d '{"groups":[1]}'

# dsadsadasd(目录ID=4) → 仅临床一科(组2)可见
curl -X PUT http://10.15.109.17:8080/api/v1/buckets/1/dirs/4/visibility \
  -H 'Content-Type: application/json' -H "Authorization: Bearer <TOKEN>" \
  -d '{"groups":[2]}'
```

| 参数 | 说明 |
|---|---|
| `groups` | 可见组 ID 数组;`[]` = 恢复不限制(公开) |
| 权限 | 目录创建者或管理员;仅影响本目录行,不递归子树 |

> 注:若桶访问等级不是 3,普通用户会被桶级拦下,先调整:
> `PUT /api/v1/buckets/1 -d '{"permission_level":3}'`

## 4. 验证结果(实测)

用各账号登录后列出桶根目录:

```bash
curl -X POST .../auth/login -d '{"username":"demo_zhang","password":"Demo123456"}'
curl -X GET "http://10.15.109.17:8080/api/v1/buckets/1/files?path=/" -H "Authorization: Bearer <demo_zhang的TOKEN>"
```

| 账号 | 根目录可见文件夹 | 越权访问结果 |
|---|---|---|
| admin | SMB演示素材、dsadsadasd、新建文件夹 | — |
| demo_zhang(信息科) | SMB演示素材、新建文件夹 | 进 dsadsadasd → `403 forbidden` |
| demo_li(临床一科) | SMB演示素材、dsadsadasd | — |
| demo_wang(无组) | 仅 SMB演示素材 | 两个科室目录均不可见 |

## 5. 演示建议(现场操作)

1. **Web 端演示**:浏览器打开 `http://10.15.109.17`,依次登录四个账号,展示同一桶下文件夹列表差异;点击无权限文件夹演示 403。
2. **SMB 端演示**(网关 60s 内同步 ACL 变更):
   ```powershell
   net use Z: /delete          # 先断开当前 admin 连接(同一服务器仅允许一个凭据)
   net use Z: \\10.15.109.17\test-bucket Demo123456 /user:demo_zhang /persistent:no
   # 资源管理器 Z 盘:可见 新建文件夹
   net use Z: /delete
   net use Z: \\10.15.109.17\test-bucket Demo123456 /user:demo_wang /persistent:no
   # 资源管理器 Z 盘:仅见 SMB演示素材
   ```
3. **SMB 多账号同时挂载**(利用多 IP,同一时刻三个账号各挂一个盘符,切换演示零等待):
   ```powershell
   net use Z: \\10.15.109.17\test-bucket Demo123456 /user:demo_zhang /persistent:no
   net use Y: \\10.15.109.18\test-bucket Demo123456 /user:demo_li    /persistent:no
   net use X: \\10.15.109.19\test-bucket Demo123456 /user:demo_wang  /persistent:no
   # Z = 信息科视角 / Y = 临床一科视角 / X = 无权限视角,三个窗口对照演示
   ```

## 6. 接口速查

| 用途 | 方法 | 路径 | 权限 |
|---|---|---|---|
| 登录 | POST | `/auth/login` | 公开 |
| 创建用户 | POST | `/auth/register` | 管理员 |
| 创建组 | POST | `/groups` | 管理员 |
| 组列表 | GET | `/groups` | 管理员 |
| 添加成员 | POST | `/groups/:id/members` `{"user_id"}` | 管理员 |
| 移除成员 | DELETE | `/groups/:id/members/:uid` | 管理员 |
| 我的组 | GET | `/users/me/groups` | 登录用户 |
| 列出目录 | GET | `/buckets/:id/files?path=/` | 登录用户(按可见组过滤) |
| 设置文件夹可见组 | PUT | `/buckets/:id/dirs/:fid/visibility` `{"groups":[]}` | 创建者或管理员 |
| 设置文件可见组 | PUT | `/buckets/:id/files/:fid/visibility` `{"groups":[]}` | 创建者或管理员 |

## 7. 网络与 IP 说明(重要)

### 7.1 多 IP 分配

演示服务器(单台 Linux 实例)的网卡 `ens33` 绑定了**多个 IP**,用于 SMB 多账号同时挂载:

```
10.15.109.17  主地址(API / SSH / SMB 默认入口)
10.15.109.18  次地址(第二账号 SMB 挂载)
10.15.109.19  次地址(第三账号 SMB 挂载)
10.15.109.16  动态地址(DHCP,可能变化)
```

> 为什么需要多 IP:Windows 对**同一服务器地址**只允许一组凭据同时连接
> (错误 1219:同一用户已用其他凭据连接)。给同一实例挂多个 IP 后,
> 不同账号可同时以不同盘符挂载,演示时直接对照,无需反复 `net use /delete`。

### 7.2 IP 变更处理(本次实操案例)

- 现象:SSH/445/8080 全部连不上 `192.168.10.205`(原动态地址已失效),Z 盘显示"已断开连接"。
- 排查:
  ```powershell
  Test-NetConnection 10.15.109.17 -Port 22     # 依次测试 17/18/19/.16
  Test-NetConnection 10.15.109.17 -Port 445
  ```
- 处理(更新 sshbox 连接配置):
  ```powershell
  cd tool
  .\sshbox.exe set host 10.15.109.17    # 更新目标主机
  .\sshbox.exe get                        # 确认
  ```
- 验证服务仍在:任意可达 IP 上 `445/8080/9000` 均在监听,`orbitcloud`/`smb-gateway` 服务 active。
- 重新挂载 Z 盘:用新 IP 替换旧 IP 执行 `net use Z: \\<新IP>\test-bucket admin123456 /user:admin /persistent:yes`。
