# OrbitCloud 构建与打包指南

本文档规范 OrbitCloud 的构建、打包与发布流程,覆盖**二进制产物**与 **Docker 版本包**两套打包体系,并给出发布前必须执行的检查清单。

## 1. 打包体系总览

| 产物 | 位置 | 用途 | 入口 |
| --- | --- | --- | --- |
| 二进制包 | `build/dist/` | 裸机/systemd 部署(Go 后端 + Rust SMB 网关 + 前端 web/) | `build/build.sh` |
| Docker 版本包 | `dist/OrbitCloud-v<版本>/` + `.zip` | Docker 一键部署(镜像 + compose + 说明) | `build/build-docker-release.ps1` |

两条流水线互相独立:二进制包面向源码部署场景,Docker 版本包面向镜像分发场景。**发版时两者都应更新**(当前仓库以 Docker 版本包为分发主通道)。

## 2. Docker 版本包一键打包

### 2.1 脚本位置与要求

- 脚本:`build/build-docker-release.ps1`(Windows / PowerShell 5.1+,UTF-8 BOM)
- 前置:本机已安装 Docker Engine(可用 `docker` 命令)
- 构建网络可达(镜像构建需拉取基础镜像与依赖)

### 2.2 用法

```powershell
# 指定版本打包(推荐,版本号必须与 config/default.yaml 一致)
powershell -ExecutionPolicy Bypass -File build/build-docker-release.ps1 -Version 1.4.6

# 缺省版本:自动读取 config/default.yaml 的 app.version
powershell -ExecutionPolicy Bypass -File build/build-docker-release.ps1
```

版本号校验:`^\d+\.\d+\.\d+$`,非法直接终止。

### 2.3 脚本流程(顺序固定,不可跳过)

1. **版本号解析**:`-Version` 参数优先,缺省读 `config/default.yaml` 的 `app.version`
2. **构建镜像**:`docker build -t orbitcloud:<版本>`(Dockerfile 多阶段:Go 后端 + Rust SMB 网关 + 前端)
3. **打 tag**:`docker tag orbitcloud:<版本> orbitcloud:latest`(compose 默认引用 latest)
4. **导出镜像**:`docker save orbitcloud:<版本> -o dist/OrbitCloud-v<版本>/orbitcloud.tar`
5. **复制 compose**:`docker-compose.yml`(单机版)与 `docker-compose.rustfs.yml`(生产版)
6. **生成使用说明**:以 `dist/` 中最近版本的 `使用说明.md` 为模板,替换全部版本号子串(覆盖 `v1.4.5`、`orbitcloud:1.4.5` 等所有出现位置)
7. **zip 打包**:`OrbitCloud-v<版本>.zip`,条目带 `OrbitCloud-v<版本>/` 目录前缀(与历史包格式一致)

### 2.4 产物结构

```
dist/OrbitCloud-v1.4.6/
├── orbitcloud.tar            镜像(docker save;部署时 docker load -i)
├── docker-compose.yml        单机开箱即用(前端 18080 / API 8080 / SMB 1445)
├── docker-compose.rustfs.yml RustFS + PostgreSQL 生产版
└── 使用说明.md               版本化部署说明
dist/OrbitCloud-v1.4.6.zip    上述目录的压缩包(分发用)
```

## 3. 发布流程规范(Checklist)

发布新版本必须按序执行,任一失败即中止:

1. **更新版本号(两处同步)**
   - `config/default.yaml` → `app.version`
   - `docker/entrypoint.sh` → `ORBITCLOUD_APP_VERSION`
   - 提交:`chore: 版本号 x.y.z -> a.b.c`
2. **全量测试**
   - `go test ./...`、`cargo test`(smb_server/rust 目录)
   - 冒烟:`powershell -ExecutionPolicy Bypass -File test/orbitcloud-smoke-test.ps1`(31 项应全绿)
   - SMB 端到端:挂载/认证/上传下载/删除目录/回收站(涉及 SMB 改动时必须)
3. **镜像验证**
   - `docker build -t orbitcloud:<版本> .`
   - 容器内 `orbitcloud --version` 输出与版本号一致
4. **一键打包**:执行 `build-docker-release.ps1 -Version <版本>`
5. **产物验证**:`docker load -i dist/OrbitCloud-v<版本>/orbitcloud.tar` 可正常导入,镜像 ID 与构建一致
6. **部署验证**:`docker compose up -d`(用最新包)healthy、admin 登录、建桶后 SMB 共享注册
7. 提交打包产物说明(产物本身在 `dist/`,不纳入版本库)

## 4. 产物使用(使用者视角)

```bash
docker load -i orbitcloud.tar
docker tag orbitcloud:<版本> orbitcloud:latest   # compose 引用 latest,先打 tag
docker compose up -d
docker exec -it orbitcloud /usr/local/bin/orbitcloud --add-superadmin admin '<强密码>'
```

详见版本包内 `使用说明.md`。

## 5. 注意事项

- **版本号一致性**:`config/default.yaml` 是权威版本源(脚本缺省读取);发布时若 `-Version` 与配置不一致,以 `-Version` 为准但属于流程违规,应在打包前先同步配置
- **使用说明模板**:以 dist 中最近版本为模板,若本次发布有重大功能变更,生成后需人工核对/补充"版本要点"章节
- **镜像尺寸**:约 196MB(磁盘)/ 50MB(导出压缩);若体积异常增大,检查是否引入了大依赖或构建缓存失效
- **Windows 行尾**:`.ps1` 需保持 UTF-8 BOM(中文注释在 PowerShell 5.1 下必须);修改后请勿以无 BOM 方式保存
