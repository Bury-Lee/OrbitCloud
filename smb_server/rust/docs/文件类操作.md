# SMB 文件类操作 —— 协议语义、实现链路与现状记录

> 覆盖对象:`smb_server/rust`(ixr-smb-server 补丁库 + RemoteBackend/RemoteHandle 适配层)
> 与 `smb_server/go`(Go 网关业务层)的全部文件类操作。
> 协议依据:MS-SMB2(2.2.x 命令 / 3.3.x 服务器行为)、MS-FSCC(信息类)。
> 帧协议契约:Rust `src/types/` ↔ Go `protocol.go`/`types.go` 两侧镜像,硬契约。

---

## 0. 总览

文件类操作共 11 个操作码(4~14),由 SMB2 协议命令翻译而来。
认证类操作码(1~3)为网关内部 RPC,不在本文范围。

| 操作码 | 名称 | 对应的 SMB2 命令 | 触发方式 |
|:---:|:---|:---|:---|
| 4 | `file_open` | SMB2_CREATE | 客户端 CREATE 请求 |
| 5 | `file_read` | SMB2_READ | 客户端 READ 请求 |
| 6 | `file_write` | SMB2_WRITE | 客户端 WRITE 请求 |
| 7 | `file_flush` | SMB2_FLUSH | 客户端 FLUSH 请求 |
| 8 | `file_stat` | SMB2_QUERY_INFO | 客户端 QUERY_INFO(File 类) |
| 9 | `file_set_times` | SMB2_SET_INFO (FileBasicInformation) | 客户端 SET_INFO |
| 10 | `file_truncate` | SMB2_SET_INFO (FileEndOfFileInformation) | 客户端 SET_INFO |
| 11 | `file_list_dir` | SMB2_QUERY_DIRECTORY | 客户端 QUERY_DIRECTORY |
| 12 | `file_close` | SMB2_CLOSE | 客户端 CLOSE |
| 13 | `file_unlink` | 无直接命令(SET_INFO 置删除位 + CLOSE 触发) | 客户端 SET_INFO(Disposition) |
| 14 | `file_rename` | SMB2_SET_INFO (FileRenameInformation) | 客户端 SET_INFO |

统一实现链路:

```text
SMB2 命令
  → patched-ixr handlers(create.rs / read.rs / write.rs / ... )
  → backend trait(ShareBackend / Handle, patched-ixr/src/backend.rs)
  → RemoteBackend / RemoteHandle(rust/src/remote_backend/backend.rs,帧协议 RPC)
  → Go 网关(operate.go 路由 → file_ops.go / file_io.go / file_dir.go)
  → OrbitCloud 后端(DB 记录 + 对象存储)
```

帧协议控制面 body 布局:`[4B jsonLen] + OperateRequest/Response JSON + [流数据段(仅 Read/Write)]`。
请求/响应的字段名、JSON tag、顺序与 Go 侧完全一致(`serde(rename_all = "camelCase")`)。

## 1. file_open(SMB2_CREATE)—— 打开/创建

### 1.1 协议语义(MS-SMB2 §2.2.13,§2.2.14)

CREATE 的核心字段被翻译为后端打开的意图:

- **CreateDisposition** 六种处置 → `OpenIntent`(patched-ixr/src/handlers/create.rs:79-86):

  | CreateDisposition | 语义 | OpenIntent | 帧协议 intent 串 |
  |:---|:---|:---|:---|
  | FILE_SUPERSEDE (0) | 已存在则替换,不存在则新建 | `OverwriteOrCreate` | `overwrite_or_create` |
  | FILE_OPEN (1) | 只打开,不存在 → `STATUS_OBJECT_NAME_NOT_FOUND` | `Open` | `open` |
  | FILE_CREATE (2) | 只创建,已存在 → `STATUS_OBJECT_NAME_COLLISION` | `Create` | `create` |
  | FILE_OPEN_IF (3) | 打开或创建 | `OpenOrCreate` | `open_or_create` |
  | FILE_OVERWRITE (4) | 只打开并清空,不存在 → NOT_FOUND | `Truncate` | `truncate` |
  | FILE_OVERWRITE_IF (5) | 打开或创建,已存在则清空 | `OverwriteOrCreate` | `overwrite_or_create` |

- **AccessMask** → 读写意图提示(create.rs:88-100):
  `FILE_READ_DATA | FILE_READ_ATTRIBUTES | GENERIC_READ | GENERIC_ALL | MAX_ALLOWED` → 请求读;
  `FILE_WRITE_DATA | FILE_APPEND_DATA | FILE_WRITE_ATTRIBUTES | DELETE | GENERIC_WRITE | GENERIC_ALL | MAX_ALLOWED` → 请求写。
- **CreateOptions**:`FILE_DIRECTORY_FILE` → 按目录打开;`FILE_NON_DIRECTORY_FILE` → 目标是目录则报 `STATUS_FILE_IS_A_DIRECTORY`;`FILE_DELETE_ON_CLOSE` → 关闭时删除。
- 只读树(ACL 只读)上:写意图打开或创建型处置 → `STATUS_ACCESS_DENIED`(create.rs:102-118)。
- 响应 CreateAction:新建 → `FILE_CREATED`(2),其余 → `FILE_OPENED`(1)。

### 1.2 期望行为(后端视角)

1. 按 intent 执行创建处置,不得偏离:Open 绝不隐式创建(Create 亦然,已存在即错);
2. `overwrite_or_create` 清空内容(截断到 0)且保留句柄;
3. 目录打开:目录不存在且为创建型 intent → mkdir(幂等);目录存在且文件型 intent → IsDirectory;
4. 返回:句柄 ID、实际类型(目录/文件)、打开时大小、是否已存在。

### 1.3 实现链路

| 层 | 位置 | 说明 |
|:---|:---|:---|
| 协议层 | patched-ixr/src/handlers/create.rs:48-194 | 解析/校验/翻译 → `backend.open(path, opts)` |
| 适配层 | rust/src/remote_backend/backend.rs:93-137 | 组装 `OpenArgs{bucket_id, path, read, write, intent, directory, non_directory, delete_on_close}` → `call_operate` |
| 网关层 | go/file_ops.go:204-384 | 共享上下文解析 → 根目录/目录/文件分支 → intent 处置 → 分配句柄 |
| 结果 | `OpenResult{handle_id, is_dir, end_of_file, exists}` | Rust 侧包成 `RemoteHandle` |

### 1.4 错误码映射(Go → Rust → NTSTATUS)

| 网关错误 | 哨兵码 | Rust SmbError | NTSTATUS |
|:---|:---:|:---|:---|
| 目标不存在(Open/Truncate) | `ERR_NOT_FOUND` | `NotFound` | OBJECT_NAME_NOT_FOUND |
| 只读共享写意图 / 无权限 | `ERR_ACCESS_DENIED` | `AccessDenied` | ACCESS_DENIED |
| 已存在(Create) | `ERR_EXISTS` | `Exists` | OBJECT_NAME_COLLISION |
| 目录当文件打开(non_directory) | `ERR_IS_DIRECTORY` | `IsDirectory` | FILE_IS_A_DIRECTORY |
| 未知 intent / 缺桶上下文 | `ERR_BAD_REQUEST` | `NotSupported` | NOT_SUPPORTED |

### 1.5 现状偏差

- `FILE_SUPERSEDE` 与 `FILE_OVERWRITE_IF` 合并为同一意图,且响应 CreateAction 缺失 `FILE_OVERWRITTEN`(3)(create.rs:169-171 固定回 OPENED/CREATED)。Windows 客户端对 CreateAction 属提示性字段,当前可容忍。

## 2. file_read(SMB2_READ)—— 按偏移读

### 2.1 协议语义(MS-SMB2 §2.2.19)

- 按 `offset` 读 `length` 字节;**返回可少于请求长度 = 读到 EOF**,0 字节 = EOF;
- 目录句柄读 → `STATUS_FILE_IS_A_DIRECTORY`;
- 读稀疏/未写区间:协议上应读到零填充;本设计明确"绝不零填充"(垃圾字节会损坏对完整性敏感的文件),返回短读(EOF 语义)。

### 2.2 期望行为

1. 不越界:读区间与对象大小/写回缓存拼装,间隙走对象范围读;
2. 写回缓存优先命中(未冲刷的写应立即可见);
3. 长度契约:响应 `ReadResult.length` 必须等于流数据段实际字节数,Rust 侧强校验(backend.rs:256-259),防协议错位。

### 2.3 实现链路

| 层 | 位置 | 说明 |
|:---|:---|:---|
| 协议层 | patched-ixr/src/handlers/read.rs | `handle.read(offset, len)` |
| 适配层 | backend.rs:238-262 | `ReadArgs{handle_id, offset, length}`;流段即数据 |
| 网关层 | go/file_io.go:30-130 | 写回缓存段 + 对象区间拼装;对象缺失/416 → 空(EOF) |

### 2.4 错误映射

| 场景 | 哨兵码 | NTSTATUS |
|:---|:---:|:---|
| 目录句柄 | `ERR_IS_DIRECTORY` | FILE_IS_A_DIRECTORY |
| 句柄不存在 | `ERR_NOT_FOUND` | OBJECT_NAME_NOT_FOUND |
| 长度契约不符 | —(Rust 侧直接报 Io) | UNEXPECTED_IO_ERROR |

## 3. file_write(SMB2_WRITE)—— 按偏移写

### 3.1 协议语义(MS-SMB2 §2.2.21)

- 按 `offset` 写数据,返回实际写入字节数;数据随帧流数据段传输;
- 目录写 → `STATUS_FILE_IS_A_DIRECTORY`;只读共享 → `STATUS_ACCESS_DENIED`。

### 3.2 期望行为

1. S3 不支持随机写 → **写回缓存(write-back)** 设计:写进入段表(重叠合并),`flush`/`close` 时整体上传;
2. 写尾超出已知大小 → 扩展已知大小(stat 立即可见);
3. 缓存总量达阈值 → 提前整体冲刷(防内存无限增长,go/write_cache.go);
4. 实际写入 = 入缓存长度,立即成功返回。

### 3.3 实现链路

| 层 | 位置 | 说明 |
|:---|:---|:---|
| 协议层 | patched-ixr/src/handlers/write.rs | `handle.write(offset, data)` |
| 适配层 | backend.rs:273-292 | `WriteArgs{handle_id, offset}` + 流段 = data |
| 网关层 | go/file_io.go:136-166 | 只读拒绝 → 缓存合并 → 阈值冲刷 |

### 3.4 注意点

- **写后未 flush 的可见性**:同一句柄内 read 优先命中缓存,可见;其他句柄/其他客户端需 flush 后才可见(写回缓存设计取舍);
- close 时上传失败:**CLOSE 响应仍成功**(backend.rs:461-476 有意吞错),数据一致性由网关侧写回重试兜底 —— 这是数据丢失风险点,见 TODO。

## 4. file_flush(SMB2_FLUSH)—— 冲刷

### 4.1 协议语义(MS-SMB2 §2.2.29)

- 将文件缓冲数据持久化到稳定存储;成功后数据对其它读者可见、且机器故障后仍存在;
- 目录句柄:无缓存,幂等成功(go/file_io.go:177-179)。

### 4.2 期望行为

1. 写回缓存整体上传对象存储;
2. 同步文件记录大小 + 桶用量对称更新(syncFileMeta,file_io.go:196-208);
3. 无缓存(未写过) → 直接成功。

### 4.3 实现链路

## 5. file_stat(SMB2_QUERY_INFO)—— 查询元信息

### 5.1 协议语义(MS-SMB2 §2.2.37 + MS-FSCC)

- QUERY_INFO(InfoType=File)常见类:FileBasicInformation(时间+属性)、FileStandardInformation(大小)、FileAllInformation(组合);
- 后端只需返回统一 `FileInfo`,协议层按类组装;
- 大小语义:文件大小 / 目录 0;时间均为 FILETIME(1601-01-01 起 100ns 刻度)。

### 5.2 期望行为

1. 大小取 `max(文件记录, 写回缓存已知值)`(未冲刷的写立即可见);
2. 桶根(虚拟根,无记录行) → 返回桶级元信息;
3. 目录 → 文件夹记录;文件 → 文件记录。

### 5.3 实现链路

## 7. file_truncate(SMB2_SET_INFO / FileEndOfFileInformation)—— 截断/扩展

## 9. file_close(SMB2_CLOSE)—— 关闭句柄

### 9.1 协议语义(MS-SMB2 §2.2.22)

- 关闭句柄并释放资源;
- 可携带 `SMB2_CLOSE_FLAG_POSTQUERY_ATTRIB` → 响应带关闭前元信息(close.rs:50-58);
- 若句柄设了 delete-on-close → 关闭后删除文件(close.rs:62-68);
- 重复关闭 → `STATUS_FILE_CLOSED`。

### 9.2 期望行为

1. 写回缓存整体上传 + delete_on_close 删除(go 侧 Close);
2. 上传失败:当前实现关闭仍算成功(错误仅日志),一致性靠网关写回重试兜底 —— 风险点见 TODO;
3. delete-on-close 的 unlink 失败仅记日志(close.rs:66-68)。

### 9.3 实现链路

## 10. file_unlink(删除)—— 标记删除的落地

### 10.1 协议语义

SMB2 **没有独立的删除命令**。删除经两种路径:

1. **SET_INFO FileDispositionInformation**(MS-FSCC §2.4.10):置 `DeleteFile` 位 → 仅标记,实际删除发生在最后一个句柄 CLOSE 时(set_info.rs:92-99 置 `delete_on_close`);
2. **CREATE 带 FILE_DELETE_ON_CLOSE**:CREATE 成功即标记,CLOSE 时删除。

协议层在 CLOSE 时统一转成 `backend.unlink(path)`(close.rs:62-68)。

### 10.2 期望行为

1. 删除路径;**目录须为空**,非空 → `STATUS_DIRECTORY_NOT_EMPTY`;
2. 目标不存在 → `STATUS_OBJECT_NAME_NOT_FOUND`;
3. 不递归删除。

### 10.3 实现链路

| 层 | 位置 |
|:---|:---|
| 协议层 | patched-ixr/src/handlers/close.rs:62-68 → `backend.unlink(path)` |
| 适配层 | backend.rs:147-162(`UnlinkArgs{bucket_id, path}`) |
| 网关层 | go/file_dir.go `Unlink`(目录须为空) |

## 11. file_rename(SMB2_SET_INFO / FileRenameInformation)—— 重命名/移动

### 11.1 协议语义(MS-FSCC §2.4.37)

- 字段:`ReplaceIfExists(1) + Reserved(7) + RootDirectory(8) + FileNameLength(4) + FileName`;
- **ReplaceIfExists=0 且目标已存在 → `STATUS_OBJECT_NAME_COLLISION`**(后端必须拒绝);
- RootDirectory 非零 = 目标名相对该句柄目录,需拼接;本实现未处理(当作全路径) —— 见 TODO;
- 同卷重命名(跨桶/卷本实现不支持,后端按同桶处理)。

### 11.2 期望行为

1. 目标已存在必须拒绝(不覆盖);
2. 重命名后句柄仍指向同一文件(协议层更新 `last_path`,set_info.rs:122);
3. 目录/文件均可移动(同桶内)。

### 11.3 实现链路

| 层 | 位置 |
|:---|:---|
| 协议层 | patched-ixr/src/handlers/set_info.rs:100-127 → `backend.rename(from, to)` |
| 适配层 | backend.rs:172-188(`RenameArgs{bucket_id, from_path, to_path}`) |
| 网关层 | go/file_dir.go `Rename`(目标已存在必须拒绝) |

### 11.4 现状偏差

- ReplaceIfExists 标志未读取校验(依赖 Go 侧无条件拒绝已存在目标,行为等价但协议不完整);
- RootDirectory 相对路径语义缺失 —— 见 TODO。
